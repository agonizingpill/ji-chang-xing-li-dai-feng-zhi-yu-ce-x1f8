# Airside Flow · 机场行李带峰值预测

`gb-1072` 是面向机场运行控制团队的行李波次预测与岗位排班应用。模拟客户是星港机场 T2 运行控制中心，团队每天把航班到达波次、转盘计数器和人工排班表合并成一张运行表，再交给值班经理决定是否加派机动人员。

## 业务范围

- 航班波次。按航站楼和到达时间窗合并航班，记录计划行李量和取消/改降标记。
- 行李带计数。每一条计数绑定波次、行李带、时间点和采集来源，重复时间点受唯一约束。
- 峰值预测。worker 消费 Redis 队列，执行 STL 风格季节分解与滚动窗口线性回归，结果和输入摘要写回 PostgreSQL。
- 人员班次。记录班次、岗位容量和确认人。计划人数超过容量时进入待值班经理确认状态。
- 拥堵复盘。记录现场峰值、排队分钟、原因与处置动作，主管关闭复盘单后完成闭环。
- 行李带停用改送。行李带临时停用后按 (波次, 行李带) 分别预测，只把停带时刻起的预测件数改投备带；多波次共用备带时合并备带原有负荷，超出容量的余量排队结转到下一档。试算带版本指纹，补报计数、调整容量或确认其他方案会使旧试算作废，重算后才能确认；确认成功后所有受影响波次一起换用新预测。

主流程是航班波次导入 → 行李带计数 → 时序分解 → 峰值预测 → 人员班次确认 → 拥堵复盘。取消或改降未完成标记时，预测请求返回 409。预测峰值超过岗位容量时，发布请求会先把班次置为 `needs_confirmation`，只有 `supervisor` 留下确认说明后才能发布。

## 算法口径

输入是按时间排序的同一波次行李带计数。STL 风格分解按 4 或 8 个采样点构造季节模板，使用移动平均获得趋势，最近 `window_size` 个去季节化点通过一元线性回归外推未来 4 个点。输出包括峰值、未来 4 点、季节强度、每小时趋势、窗口大小、周期和输入快照 SHA-256。固定演示种子记录为 `1072`，演示训练数据是 seed 生成的合成计数。

## 行李带停用改送

登录后打开侧边栏「改送值班」。值班经理和调度员可以发起试算，观察员只读；确认改送与调整备带容量仅值班经理可操作。

- **按带分别预测**：每个 `(波次, 行李带)` 独立做 STL 风格分解与滚动回归，外推未来 4 个 10 分钟时间档；停用带只把 `stop_at` 及之后的整档预测件数改投备带，停带前的档保留原负荷。
- **共用备带与排队**：多个波次共用一条备带时，备带自身（原有）预测与各波次转入量按时间档合并；单档 `上档积压 + 本档到件` 超过备带容量时，余量作为本档结束积压结转到下一档，页面逐档展示原有负荷、转入量、峰值负荷、容量、消化量和积压。
- **试算失效与重算**：每次试算对参与行李带的计数快照、容量和当时已确认方案计算 `basis_hash`。补报计数（`POST /counts`）、调整容量（`PATCH /reroute/belts/{belt_code}/capacity`）或确认另一个改送方案都会让未确认试算作废（`superseded`）；确认接口在事务内复核指纹，不一致即返回 409，需要重新试算（`POST /reroute/plans/{id}/recalc`）后再确认。
- **确认换用新预测**：确认成功后，所有受影响波次在同一事务内各生成一条 `published` 的 `peak_forecasts` 记录（结果中带 `reroute_plan_id` 溯源），波次状态置为 `forecasted`，同一对行李带的其他在途试算一并作废。
- **值班页面**：可发起试算、重新试算、经理确认，并查看每条行李带的基线峰值、容量是否超窗、逐波次预测迷你图、备带逐档峰值与积压，以及历史方案的作废原因。

改送相关表为 `belts`（行李带登记、容量与备带标记）和 `belt_reroute_plans`（试算/作废/确认状态机、指纹与逐档结果 JSONB），领域逻辑在 `backend/src/reroute_engine.py`（纯标准库试算引擎）、`reroute_service.py` 与 `reroute_routes.py`。

## 技术结构

- `backend/src/app.py` 提供认证、领域路由、状态前置条件和审计记录。
- `backend/src/algorithm.py` 提供可复现的 STL 风格分解与滚动预测。
- `backend/src/worker.py` 负责 Redis 队列消费、失败写回和心跳文件。
- `backend/src/db.py` 创建 PostgreSQL 领域表和审计表。
- `backend/scripts/seed_demo.py` 使用业务编号和唯一约束实现幂等 seed。
- `frontend/src/app.js` 和 `frontend/src/styles.css` 提供原生 HTML/CSS/JS 控制台。

共享枚举在后端 `db.py` 的 CHECK 约束、前端 `badge()` 的状态字典和 `app.js` 的角色文案中分别定义。JWT 认证、审计日志、请求 ID 和错误响应是横切能力。


## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **行李带计数覆盖审计** 核对波次是否有有效采样、计数是否落在到达窗口内。窗口外采样须由值班人员复核。
- **排班重叠核对** 同航站楼的有效班次若时段重叠，交值班经理确认岗位能否并行覆盖。相邻但互不重叠的班次不计为冲突。
- **峰值预测兑现追踪** 对照预测峰值与拥堵复盘实测，高出预测的高峰交给下轮模型校准。
- **峰值时点保障缺口** 只统计覆盖预测峰值时点的已确认班次容量；系统显示预计尚缺的保障量。

### 二次扩展核验

- **取消与备降波次核销** 对照航班波次标记与最近预测状态，优先处理取消未标和停用波次中的遗留发布。
- **首件行李接驳偏差** 逐波次和行李带定位首个实际有件的有效计数，对照波次窗口识别等待或时间对齐异常。
- **拥堵复盘行动回收** 按复盘行动、当时排队分钟和处置状态分拣主管待关闭事项。

## 业务处置与验收

登录后打开「航班波次保障与交接」。操作员提交结果、凭证号和说明，主管可复核关闭或退回补证，观察员可查看记录。关闭时复查源业务状态，处置历史保留每次操作。

- 取消备降波次发布核销
- 首件接驳放行
- 峰值班组保障验收
- 拥堵复盘对外交接
- 波次发布与保障看板
